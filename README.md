# 像素无限世界·纪元生存

一个纯前端、零依赖的 2D 像素沙盒生存游戏。整个游戏是**一个 HTML 文件**（约 1.3 万行代码，770 KB），双击就能玩，也能挂在任何静态站点上。

- 无构建步骤、无第三方库、无联网素材，所有美术资源以 base64 内嵌，离线可玩
- 无限世界：按种子程序化生成地形、生物群系、村庄、王宫、强盗城池、女巫小屋
- 生存循环：采集 → 合成 → 建造 → 农耕 → 战斗 → 交易 → 睡觉度夜
- 多人联机：走公共 MQTT 中转（EMQX / HiveMQ / Mosquitto），无需自建服务器

## 快速开始

```bash
# 方式一：直接双击 index.html
# 方式二：起一个本地静态服务
python3 -m http.server 8080    # 然后访问 http://localhost:8080/
```

在线试玩地址见仓库 About 里的链接（若已部署）。

## 操作

| 按键 | 作用 |

| W A S D / 摇杆 | 移动 |
| 空格 | 挖脚下那格（镐等级决定能挖什么矿） |
| Q | 拆/挖**面前一格**：砍树、拆木块石砖、拆门箱家具、采花采果、捡书和藏宝图 |
| Y | 交互：开门开箱、睡觉、收麦、喂狼驯服、上王座、篝火烤肉、和村民交易、雇守卫 |
| E | 攻击 / 射箭 / 丢雪球 |
| R | 放置手持的方块或家具 |
| F / G / Shift | 疾跑 / 潜行 / 举盾 |
| C / U / I / B | 吃 / 丢弃 / 背包 / 书架 |
| 1-9、滚轮 | 切快捷栏 |
| T | 聊天（以 `/` 开头是控制台指令） |

Y 从不破坏方块，Q 从不触发交互 —— 这条边界是刻意设计的，改代码时别打破它。

## 世界与系统

- **区块式无限地图**：16×16 格的区块按需生成与卸载，只有玩家附近才模拟实体
- **生物群系**：平原、森林、雨林、沙漠、雪原、高山、海洋、河流，海岸线与河流由噪声阈值切割
- **结构**：村庄（房屋、农田、集市、教堂、铁匠铺）、王宫（王座、旗帜、宝箱、守卫、国王、床）、强盗城池（强盗与首领，定期出营抢村）、女巫小屋（卖药水的中立商人）
- **派系战争**：两个王宫势力互相派兵攻打对方王宫，只在你靠近时才开打
- **昼夜与生存**：一天 600 秒，夜里村民回床、狼更凶；饥饿、体温、装备减伤、附魔、任务链、钓鱼、农耕、繁殖
- **存档**：自动写入 localStorage，多存档位；改动的方块、玩家放置的家具与地板都会持久化

## 代码地图

想改东西，从这里进去最省事：

| 位置 | 内容 |
| --- | --- |
| `OBJ`（约 1058 行） | 全部方块/家具定义：硬度、掉落、是否实心、能否拾取 |
| `ANIMALS`（约 3185 行） | 全部生物：血量、速度、敌对标记、掉落 |
| `RECIPES`（约 5252 行） | 合成配方表 |
| `makeChunk`（约 3038 行） | 区块生成总入口：地形、结构、物件合并 |
| `villageFor` / `palaceObjFor` / `fortAtCell` / `hutAtCell` | 村庄 / 王宫 / 强盗城池 / 女巫小屋的布局生成 |
| `updateEntity`（约 8594 行） | 所有生物 AI 的唯一分支链 |
| `nearestInteract` / `hitObject` / `doDigFront` | Y 交互、Q 拆除、拆分逻辑 |
| `drawTile`、渲染列表（约 10700 行起） | 瓦片与物件的绘制顺序 |
| `SKINS` / `buildImgSkin`（约 3427 行） | 主角皮肤与逐帧烘焙的走路动画 |

两个容易踩的坑，本项目已经踩过：

1. **一格只有一个物件槽**。结构生成器如果同时往一格推「地板」和「家具」两条记录，`objMap` 只记得住后一条，另一条会变成看得见摸不着的孤儿对象。正确做法是把地板沉到家具的 `_floor` 字段里（见 `makeChunk` 里的同格合并）。
2. **坐标、朝向、镜像**。立绘默认朝右，向左走时整体 `scale(-1,1)` 镜像；皮肤数据里用 `face:-1` 标记天生朝左的素材。

## 二次开发

- 全程原生 JavaScript + Canvas 2D，没有框架。改完存盘刷新即可看到效果。
- 想要自己的世界，把随机种子换掉即可（`Esc` 菜单里可输入种子）。
- 只发布单个 `index.html` 就能跑；仓库里就是这一个文件，方便 fork 后自己改着玩。
- 联机默认连公共 MQTT broker，人多时会慢；想稳定就自建一个，改 `MQTT_BROKERS` 数组。
